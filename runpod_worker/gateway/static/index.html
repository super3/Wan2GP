Video Generation API

Five or ten seconds of 832×480 video with synchronized audio, from a text prompt. One HTTP call.

Endpoints

POST /v1/videos

Submits a prompt and returns the mp4 itself. The connection is held while the video generates — normally about a minute.

curl -X POST https://HOST/v1/videos \
  -H "Authorization: Bearer sk_live_…" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "integrated_multimodal_description: …", "duration_s": 5}' \
  -o out.mp4 --max-time 300

The body is the video, so everything else comes back on headers:

HeaderExample
X-Video-Ida4d72432-…
X-Seed729184630 — pass it back to reproduce a generation exactly
X-Duration-Seconds10.125
X-Width / X-Height832 / 480
X-Has-Audiotrue
X-Generate-Seconds55.8
Field
promptRequired. The three-block format below.
duration_sOptional. 5 (default) or 10. Anything else is a 422 — the model's frame lattice only admits certain lengths.
seedOptional integer. Omit or -1 for random.
backgroundOptional. true returns a job id immediately instead of the file. Use it from a browser — a held connection dies when a phone locks its screen.

When it can't finish in time

A warm 5-second generation is around 22 seconds and a 10-second one around 56. If no worker is running, one has to boot first, which adds 90–330 seconds — longer than most HTTP timeouts. Rather than failing and discarding a job that is already running, the call returns 202 with an id:

{"id": "…", "status": "processing", "poll_url": "/v1/videos/…"}

with Location and Retry-After: 30. Handle 202 and poll the two routes below. In steady use you will rarely see it.

GET /v1/videos/{id}

{"id":"…","status":"queued"|"processing"|"completed"|"failed",
 "seed":7,"duration_s":10.125,"width":832,"height":480,
 "has_audio":true,"size_bytes":2412597,
 "content_url":"/v1/videos/…/content"}

GET /v1/videos/{id}/content

The mp4 bytes for a completed job.

GET /v1/health

Queue depth and worker capacity. No authentication required.

Status codes

CodeMeaning
200The mp4 is in the body.
202Still generating past the synchronous limit. Poll poll_url.
401Missing or invalid API key.
404No such job, or it belongs to another key.
429Daily limit reached for this key.
502Generation failed. The reason is in detail.
503Backend unavailable; the request was not charged against your quota.

What to expect

Output5.17 s or 10.125 s, 832×480, H.264 + AAC, 1–2.5 MB
Warm~22 s for 5 s, ~56 s for 10 s, returned inline
Cold start+90–330 s, returned as 202 + job id
AudioGenerated with the video and synchronized to it

Generation is not deterministic across seeds, but a fixed seed with an identical prompt reproduces the same video.
