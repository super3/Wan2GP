# Endless TV

A public TV guide whose channels are generated by MiniMax H3 on rented GPUs. The GPU boxes upload what they make
(clips, logos, posters, run results) to this app, which keeps it on a Railway volume, so the boxes can be thrown away
as soon as their clips are saved.

- **Guide** (`/`): the selected program on top, playing live, and a two-hour grid of every channel.
- **Watch** (`/watch/<channel>`): one channel full screen, with sound, channel up/down (arrow keys), mute (`m`) and full screen (`f`).
- **Live**: each channel plays its clips in a loop counted from one fixed moment, so every viewer sees the same thing at
  the same time. Its schedule (the programs in the guide) repeats the same way.

Plain Node (22+) and Express 5, no build step. The pages are static HTML, CSS and JavaScript in `public/`.

## Deploy on Railway

Railway stops reading `railway.toml` on 2026-12-01 (its "Config as Code" is deprecated), so the service is described in
the current format, `.railway/railway.ts`: the repo and folder, the healthcheck, the restart policy, and a 5 GB volume at
`/data`.

**With the Railway CLI** (5.42.1 or newer):

```bash
cd endless-tv
npm install                  # the `railway` package the config imports
railway login
railway link                 # pick (or create) the project
railway config plan          # shows what will be created
railway config apply
```

Then, in the service's settings:

1. **Variables**: add `INGEST_TOKEN`, a long random string, for example
   `node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"`. The config keeps its value
   (`preserve()`) and never contains it.
2. **Networking**: generate a domain (or add yours). Optionally uncomment `cdn` in `.railway/railway.ts` and apply again,
   so Railway's edge serves the clips instead of the app.

**In the dashboard instead**: New service from the GitHub repo `super3/Wan2GP`, branch `feature/endless-tv` (its PR;
`main` once it merges), then in its settings:

| Setting | Value |
|---|---|
| Root Directory | `/endless-tv` |
| Watch Paths | `/endless-tv/**` |
| Start Command | `npm start` (the default) |
| Healthcheck Path | `/health` |
| Volume | add one, mounted at `/data` |
| Variables | `INGEST_TOKEN` (as above), `DISCORD_URL` (your invite, for the header's button) |
| Networking | generate a domain |

Check it: `https://<domain>/health` answers `{"status":"ok","persistent":true,"uploads":true,...}`. `persistent: false`
means no volume is attached (uploads would be lost at the next deploy); `uploads: false` means `INGEST_TOKEN` is not set.

Railway notes: a service with a volume restarts with a few seconds of downtime on each deploy, and can't have replicas.
Volumes are 0.5 GB on the free plan, 5 GB on Hobby, 50 GB on Pro.

## Publish from a GPU box

`tools/publish.py` needs only Python 3.8+. The server and token come from the environment:

```bash
export ENDLESS_TV_URL=https://<domain>
export ENDLESS_TV_TOKEN=<INGEST_TOKEN>

# the six channels of the design, with their logos, posters and first clips, from a folder holding the files seed/channels.json names
python3 tools/publish.py seed seed/channels.json --media /path/to/media

# one channel
python3 tools/publish.py channel laugh-track --number 103 --name "Laugh Track" --genre Comedy --logo logo.svg --poster poster.jpg

# a clip (its length is read from the MP4), and a long prompt from a file
python3 tools/publish.py clip laugh-track clip_00003.mp4 --title "Open Mic" --prompt-file prompt.txt --seed 42

# a whole H3 Live session folder: its clips in order, with their prompts, seeds and times, and its numbers as a run
python3 tools/publish.py session laugh-track outputs/h3_live/live_20261124-001054

python3 tools/publish.py run results.json --id preload-v2012     # results of a GPU run
python3 tools/publish.py list
python3 tools/publish.py delete-clip laugh-track <clip id>
```

## API

Reads are public; writes need `Authorization: Bearer <INGEST_TOKEN>`.

| Method and path | What it does |
|---|---|
| `GET /health` | status, whether storage is persistent and uploads are on, channel and clip counts |
| `GET /api/channels` | every channel with its schedule and clips, and the server's clock (`now`, in ms) |
| `GET /api/channels/:id` | one channel |
| `PUT /api/channels/:id` | create or update: JSON `{number, name, genre, blurb, schedule: [{title, episode, blurb, badges, minutes, isNew}]}` |
| `PUT /api/channels/:id/logo` and `/poster` | the image as the body: PNG, JPEG, WebP, or SVG without scripts |
| `POST /api/channels/:id/clips` | the MP4 as the body; `?title=&seed=&sequence=&run=&generate_s=`; a long prompt URI-encoded in `X-Clip-Prompt` |
| `DELETE /api/channels/:id`, `DELETE /api/channels/:id/clips/:clipId` | remove a channel (with its files) or a clip |
| `POST /api/runs`, `GET /api/runs` | save the JSON results of a GPU run; the latest 50 |
| `GET /media/:channel/:file` | the files; their names never repeat, so they are cached for good |

Channel ids are lowercase letters, digits and dashes. Uploads land in `tmp/` on the volume, so moving them into place is
a rename; `channels.json` is replaced atomically. Uploaded SVGs that contain scripts are refused, and every media file is
served sandboxed.

## Settings

| Variable | Default | |
|---|---|---|
| `INGEST_TOKEN` | none (uploads off) | the upload token |
| `RAILWAY_VOLUME_MOUNT_PATH` | set by Railway | where uploads are kept |
| `DATA_DIR` | `./data` | overrides the volume path (local runs) |
| `MAX_UPLOAD_MB` | 300 | largest upload |
| `KEEP_CLIPS` | 0 (all) | clips kept per channel; the oldest are deleted first |
| `DISCORD_URL` | none (no button) | the invite the header's **Join our Discord** button opens; only an `https://` link is used |
| `PORT` | 3000 | set by Railway |

## Develop

```bash
npm install
INGEST_TOKEN=dev npm run dev       # http://localhost:3000, data in ./data
npm test                           # 100% coverage required
npm run check:railway              # type-checks .railway/railway.ts against the railway package
```
